# Design v2 — LIFF web ปรับให้เข้ากับแบรนด์ Rich Menu

วันที่: 2026-10-11 | branch: `feat/design-v2` | ผู้เขียน: Panda (UX/UI)
ขอบเขต: เปลี่ยนทั้งธีมและ layout ของ `public/liff` โดย **ทุก element id, ข้อความปุ่ม, aria attribute และพฤติกรรม JS เดิมต้องใช้งานได้เหมือนเดิม** (เทสต์ `app.dom.test.mjs`, `tokens.test.mjs`, `style.test.mjs` ต้องผ่านโดยไม่แก้ หรือแก้เฉพาะส่วนที่ระบุในหัวข้อ 5.3)

สรุปแนวคิดหนึ่งบรรทัด: "พื้นขาวอมฟ้า + แถบน้ำเงิน royal blue + ปุ่ม CTA เหลืองตัวหนังสือดำ + ไอคอนเส้นหนาสีน้ำเงิน + มาสคอตลุงแว่นดำในวงกลม" ตรงตาม Rich Menu

ผลสอบ contrast ทุกตัวเลขในเอกสารนี้คำนวณด้วยสูตร WCAG (สคริปต์เดียวกับ `tokens.test.mjs`) ไม่ได้ประมาณ

## 1. วิเคราะห์แบรนด์จาก Rich Menu

อ้างอิง `images/1.webp` (2000x1349) และ `rich-menu-v2-grid.jpg`

### 1.1 Palette (ค่าที่ประมาณจากภาพ แล้วปรับให้ผ่าน AA)

| บทบาท | ค่าที่เห็นใน Rich Menu | ค่าที่ใช้ใน web | หมายเหตุ |
|---|---|---|---|
| Royal blue (พื้นหลังแผงซ้าย, ไอคอน, เส้น) | ~#1157C5 | `#1157c5` | ขาวบนน้ำเงินนี้ 6.58:1 ผ่าน AA ทั้งข้อความปกติ |
| Blue เข้ม (กดค้าง, ตัวอักษรบนพื้นฟ้าอ่อน) | ไม่มีในภาพ | `#0b3c8f` | ขาวบน `#0b3c8f` 10.21:1 |
| Blue อ่อน (พื้นไอคอนหมวด, chip) | ไม่มีในภาพ | `#e6eefc` | น้ำเงิน `#1157c5` บน `#e6eefc` 5.64:1 |
| เหลือง (ปุ่ม Click, ribbon "หารบิล") | ~#FFDE59 | `#ffde59` | ดำ `#111111` บนเหลืองนี้ 14.25:1 |
| ดำ (หัวข้อ, ข้อความบนปุ่มเหลือง) | ~#111 | `#111111` ใช้บนปุ่ม, `#0f172a` ใช้เป็น text ทั่วไป | ดำอมน้ำเงินเล็กน้อยเข้ากับพื้นฟ้า |
| ขาว / เทาอ่อนมาก (พื้นหลังแผงขวา) | #FFFFFF ถึง #F7F7F7 มีลายสามเหลี่ยมจางๆ | `#ffffff` (surface), `#f3f6fc` (bg) | bg เอียงไปทางฟ้าเล็กน้อยให้การ์ดขาวลอยขึ้นโดยไม่ต้องใช้เงาหนัก |
| เขียว / แดง | ไม่มีใน Rich Menu | คงเดิม `#1d7a35` / `#d70015` | เป็นสีความหมาย (รายรับ/รายจ่าย) ห้ามเปลี่ยนเป็นสีแบรนด์ |

กฎการใช้สี: น้ำเงิน = แบรนด์/โครงสร้าง/ลิงก์, เหลือง = การกระทำหลัก (CTA) และจุดเน้นเดียวต่อหน้าจอ, เขียว/แดง = ความหมายเงินเข้า/ออกเท่านั้น

### 1.2 Type scale

Rich Menu ใช้ตัวอักษรไทยหนามาก (น้ำหนักประมาณ 700-800) หัวข้อใหญ่ ตัวรองบางและเล็กกว่ามาก (ดูข้อความ "กินด้วยกัน จ่ายด้วยกัน" เทียบกับ "หารบิล ง่ายนิดเดียว")

| ระดับ | ขนาด / น้ำหนัก / line-height | ใช้กับ |
|---|---|---|
| display | 40px / 800 / 1.15 | ยอดคงเหลือ (`.stat.balance .stat-value`, `.balance-value`) |
| h1 | 20px / 800 / 1.3 | `#page-title` ใน app bar |
| h2 | 20px / 800 / 1.3 | หัวข้อ section (`.chart h2`, `.budgets h2`, ... ) และหัวข้อ dialog |
| body | 16px / 400 / 1.5 | ข้อความทั่วไป, input |
| strong | 16px / 700 / 1.4 | ชื่อรายการ, ปุ่ม |
| secondary | 14px / 400 / 1.45 | note, hint, label |
| caption | 13px / 400-700 / 1.4 | ขั้นต่ำสุดของทั้งแอป (ปรับ 12px เดิมทั้งหมดเป็น 13px) |

บังคับ line-height >= 1.3 กับหัวข้อ เพราะภาษาไทยมีสระ/วรรณยุกต์ซ้อนบนและล่าง line-height 1.1 จะตัดตัวอักษร (ยกเว้น display ตัวเลขล้วน 1.15)

ฟอนต์: ใช้ stack เดิม `system-ui, "Leelawadee UI", Tahoma, sans-serif` เป็นฐาน และ weight 700/800 ทำงานได้ทั้ง iOS (Thonburi/Sukhumvit) และ Android (Noto Sans Thai) ตัวเลือกเสริม (Phase 8) ฝัง Prompt 600/700 แบบ self-host เพื่อให้ใกล้ Rich Menu ที่สุด ไม่บังคับ

### 1.3 Shape language

- ปุ่ม: pill เต็มรูป (`border-radius: 9999px`) ความสูงประมาณ 90px จากภาพกว้าง 260px (อัตราส่วน ~ 3:1) แต่ web ใช้สูง 44-48px
- กล่อง/ไอคอนพื้นทึบ (ลูกโป่ง "?"): สี่เหลี่ยมมนมาก รัศมีประมาณ 25-30% ของด้าน -> การ์ดใช้ radius 24px, bottom sheet 28px
- วงกลม: badge มาสคอต, ไอคอนโลก -> badge หมวดและ avatar เป็นวงกลม
- ribbon: แถบเหลืองปลายมน มีขอบพับมุมขวาบน -> ใช้กับชื่อหน้าบิล (หัวข้อ 3.12)
- ไม่มีเงาหนัก ภาพเรียบ flat; web ใช้เงาบางมาก `0 1px 2px` เพื่อแยกการ์ดจากพื้นเท่านั้น

### 1.4 Iconography

ไอคอนเส้นหนาสีน้ำเงินเดียว (stroke ประมาณ 10% ของขนาด, ปลายมน, มุมมน) บางตัวเป็นพื้นทึบ (ลูกโป่ง ?) สอดคล้องกับ sprite ปัจจุบันที่เป็น `fill:none; stroke:currentColor` อยู่แล้ว -> เปลี่ยนแค่ `stroke-width` 1.8 เป็น 2.2 (nav 2.4) และสีเป็น `--primary` ไม่ต้องวาด sprite ใหม่ ไอคอนมี 2 โทนเท่านั้น: น้ำเงิน และเขียว (หมวดรายรับ)

### 1.5 มาสคอต

ลุงผมขาว ใส่แว่นดำ ถือสมุดบัญชี "รายรับ/รายจ่าย" อยู่ในวงกลมขอบน้ำเงินมุมซ้ายบน ใช้เป็น "ตราแบรนด์" ไม่ใช่ภาพตกแต่งขนาดใหญ่ -> ใช้ที่ app bar ทุกหน้า และ hero ของหน้าบิล (หัวข้อ 3.13) ไม่ใช้ใน empty state (ต้องแก้ JS `empty-state.mjs` และเทสต์ผูกกับ symbol)

## 2. Design tokens ใหม่ (`public/liff/tokens.css`)

### 2.1 ข้อจำกัดของไฟล์ที่ต้องรักษา

- `tokens.test.mjs` อ่านค่าด้วย regex `--([a-z-]+):\s*(#[0-9a-fA-F]{6})\s*;` -> **ชื่อ token สี ต้องมีเฉพาะ a-z และ `-` (ห้ามมีตัวเลข เช่น `--blue-700` จะไม่ถูกอ่าน)** และค่าต้องเป็น `#rrggbb` 6 หลัก (ห้ามใช้ `rgb()` / 3 หลัก / 8 หลัก สำหรับ token ที่อยู่ในคู่ทดสอบ)
- ห้ามมีข้อความ `prefers-color-scheme` ในไฟล์นี้ แม้ในคอมเมนต์ (เทสต์ `not.toContain`)
- ต้องคงชื่อ token เดิมทุกตัว (เทสต์และ style.css อ้างอยู่)
- token ที่ไม่ใช่สี (radius, shadow, font-size) ใส่ในไฟล์เดียวกันได้ เพราะ regex ไม่จับ แต่ขอแยกบล็อกคอมเมนต์ให้ชัด

## 3. สเปกคอมโพเนนต์

ใช้ selector เดิมทั้งหมด การเปลี่ยนจะเกิดที่ CSS เป็นหลัก ที่ต้องเพิ่ม markup มีระบุใน 5.2

### 3.1 App bar (`.top-sticky`, `.bar`, `#page-title`, `#month`)

- `.bar` เป็นแถบน้ำเงิน: `background: var(--primary); color: var(--on-primary); border-bottom: none; padding: max(10px, env(safe-area-inset-top)) 16px 12px; min-height: 68px; border-radius: 0 0 var(--radius-card) var(--radius-card);`
- `.top-sticky` คง `background: var(--bg)` เพื่อให้มุมมนด้านล่างของแถบไม่โปร่งเห็นเนื้อหาที่เลื่อนอยู่ข้างหลัง
- มาสคอต: `<img class="bar-mascot">` ขนาด 44x44 อยู่ซ้ายสุด ก่อน `h1` (ดู 3.14) `.bar` จัด `display:flex; align-items:center; gap:12px;` `h1 { flex:1; min-width:0; }`
- `#page-title`: 20px / 800 / สีขาว (`--on-primary`) บนน้ำเงิน 6.58 ผ่าน
- `#month` (input type=month): pill ขาวบนแถบน้ำเงิน `background: var(--surface); color: var(--text); border: none; border-radius: 9999px; min-height: 44px; padding: 0 14px; font: inherit; font-weight: 700; font-size: 15px;`
- focus ring ในแถบ: `.bar :focus-visible { outline: 3px solid var(--cta); outline-offset: 2px; }` เหลืองบนน้ำเงิน 4.96 (>= 3)
- เมื่อ `monthEl.hidden` (แท็บรอบเดือน/โปรไฟล์) `h1` ยืดเต็ม ไม่มีส่วนใดกระโดด เพราะความสูงแถบกำหนดด้วย `min-height: 68px`

### 3.2 Banner (`#banner`, `#banner-retry`, `.notice`)

- `.notice`: พื้น `--notice-bg`, ตัวอักษร `--notice-text` (8.20), ขอบ `2px solid var(--cta)`, radius 16px, ขนาด 14px (จาก 13px), padding 12px 14px
- `#banner-retry` เป็นปุ่ม secondary (3.4) ชิดซ้ายใต้ข้อความ
- `role="status"` และ `aria-live` เดิมคงไว้

### 3.3 Bottom nav (`.bottom-nav`, `.nav-button`)

- `.bottom-nav`: พื้นขาว, `border-top: none; box-shadow: var(--shadow-nav); border-radius: 24px 24px 0 0;` ความสูงรวม 68px + safe-area
- `.nav-button`: `min-height: 64px; font-size: 13px; font-weight: 600; color: var(--muted); gap: 2px;`
- ไอคอน: `.nav-button .icon { stroke-width: 2.4; box-sizing: content-box; width: 24px; height: 24px; padding: 4px 16px; border-radius: 9999px; }` (svg ชั้นนอกรับ padding/background ได้ จึงเป็น "pill" หลังไอคอนโดยไม่ต้องเพิ่ม DOM)
- เลือกอยู่ (`[aria-current="page"]`): `color: var(--primary); font-weight: 800;` และ `.icon { background: var(--cta); color: var(--on-cta); }` คือ pill เหลืองหลังไอคอนดำ เหมือนปุ่ม "Click" ใน Rich Menu
- เหตุผลด้านการเข้าถึง: pill เหลืองบนขาวมี contrast พื้นเพียง 1.33 จึง **ห้ามใช้เป็นตัวบอกสถานะอย่างเดียว** ตัวบอกจริงคือ ป้าย label เปลี่ยนเป็นน้ำเงิน 6.58 + หนาขึ้น และ `aria-current="page"` ที่ screen reader อ่าน
- focus: `outline: 3px solid var(--primary); outline-offset: -3px; border-radius: 16px;`
- ห้ามเพิ่มข้อความใน `<button>` (เทสต์เทียบ `textContent` กับ label เช่น `'รายการ'`) ใช้ได้เฉพาะ CSS
- `main#app` `padding-bottom` จาก `76px` เป็น `calc(88px + env(safe-area-inset-bottom))`

### 3.14 มาสคอต (ไฟล์ asset)

ตัดจาก `1.webp` (2000x1349) ได้ตรวจด้วยสคริปต์จริงแล้วว่าตำแหน่งตรงกับวงกลม

- crop box: **left=8, top=6, right=194, bottom=192** (กว้าง x สูง 186 x 186 px) จุดศูนย์กลางประมาณ (101, 99) ของภาพต้นฉบับ
- ใส่ mask วงกลมโปร่งใส (alpha) เส้นผ่านศูนย์กลางเต็มกรอบ เพื่อตัดมุมสีขาวของ quarter-circle ในภาพออก (บนแถบน้ำเงินจะไม่เห็นมุมขาว)
- ขยายเป็น 192x192 px (Lanczos) แล้วบันทึกเป็น **WebP** `public/liff/assets/mascot.webp` คุณภาพ 88, ใช้ alpha, เป้าไฟล์ < 15 KB (PNG ที่ทดสอบได้ 63 KB ไม่ควรใช้) ต้นฉบับมีความละเอียดแค่ 186px จึงแสดงที่ 44-72 CSS px ได้คมถึง 3x
- ใช้ Python/Pillow (มีบนเครื่อง ต้องรัน `python -I`) หรือ `sharp` (มีใน node_modules)

```python
from PIL import Image, ImageDraw
im = Image.open("1.webp").convert("RGBA")
c = im.crop((8, 6, 194, 192)).resize((192, 192), Image.LANCZOS)
m = Image.new("L", (768, 768), 0); ImageDraw.Draw(m).ellipse((0, 0, 767, 767), fill=255)
c.putalpha(m.resize((192, 192), Image.LANCZOS))
c.save("public/liff/assets/mascot.webp", quality=88, method=6)
```

- ตำแหน่งที่ใช้: (1) app bar ทุกหน้า 44px (2) hero หน้าบิล 72px (ดู 3.15) ไม่ใช้ที่อื่น เพื่อให้เป็นตราแบรนด์ ไม่รก

| เทสต์ `createEmptyState` ใช้ href `#empty-*` | ไม่แตะ sprite id |
| `<img>` ใหม่ใน jsdom | ไม่โหลดภาพ จึงไม่กระทบ; ใส่ `alt=""` และ width/height |
| ปุ่ม disabled ต้องดูต่างจากปุ่มใช้งาน (เคยมีบั๊กปุ่มดูเหมือน disabled แต่กดได้ และกลับกัน) | ใช้ `:disabled` selector จริงเท่านั้น ไม่ใช้ class จำลอง |
| ปุ่มใหม่เล็กกว่า 44px | ตรวจ `.friend-remove`, `.bill-member-paid`, checkbox ในฟอร์มบิล (แถวต้อง >= 44px) |

## 6. State matrix (UX)

โปรเจกต์นี้เป็นการเปลี่ยนภาพ ไม่มี network call ใหม่ ตารางด้านล่างคือสถานะที่ต้องเห็นต่างกันชัดเจนในธีมใหม่ (ทุกข้อ "ต่างกันหรือไม่" ต้องยืนยันด้วย screenshot ของ hawk)

| state | ผู้ใช้เห็น (ธีมใหม่) | แยกจากสถานะอื่นได้หรือไม่ | ทำอะไรได้ |
|---|---|---|---|
| loading | skeleton สีฟ้าอ่อนขนาดเท่ากล่องจริง + ข้อความ sr-only | ได้ (shimmer) ต้องเช็กไม่ให้เหมือน empty | รอ |
| error | `.budgets-error` ข้อความ + ปุ่ม "ลองใหม่" แบบ secondary ขอบน้ำเงิน; `.error` แดงใน dialog | ได้ (มีข้อความ+ปุ่ม) | ลองใหม่ |
| empty success | วงกลมฟ้าอ่อน + ไอคอนน้ำเงิน + หัวข้อหนา + hint | ได้ (ไม่มี shimmer ไม่มีปุ่ม retry) | อ่านวิธีบันทึกในแชต |
| timeout / ไม่ resolve | ใช้ gate/banner เดิมของ app (`#banner` + `#banner-retry`) | ได้ (banner เหลืองขอบเหลือง) | ลองใหม่ |
| no permission | ไม่มีสถานะนี้ในการเปลี่ยนครั้งนี้ ปุ่มที่ยังไม่พร้อมใช้ `disabled` (`#bill-new`, `#export-button`, `#recurring-add`) | ได้ (พื้น `--disabled-bg`, ตัวอักษร muted, cursor not-allowed) | รอจนโหลดเสร็จ |

Browser check สำหรับ `hawk` (Panda ไม่มี browser):
1. หน้ารายการที่ 360, 390, 430px: ตรวจว่าชื่อหมวด/ยอดไม่ทับกัน, ยอด 8 หลัก (10,000,000) ใน `.stat-value` ตัดบรรทัดได้ ไม่ล้นไทล์
2. nav ที่ 360px: label "จัดการงบ", "รอบเดือน" ไม่ถูกตัด pill เหลืองไม่ล้นความกว้างปุ่ม (5 ปุ่ม x 72px)
3. ปุ่ม disabled vs ใช้ได้: `#bill-new` ก่อน/หลังโหลด และ hover/แตะปุ่ม disabled ไม่มี event
4. หน้าบิล `?tab=bills`: ribbon ชิดขอบขวา, hero เลื่อนหายแต่แถบบนติดอยู่, ยอดแบบ error state (`#bills-error` + retry) ต้องเห็นข้อความจริง
5. ยอดติดลบในโปรไฟล์: ไทล์ขาวตัวแดงบนแผงน้ำเงิน
6. dialog ฟอร์มสร้างบิลเมื่อมีเพื่อน 8+ คน: footer sticky ไม่บังช่องที่โฟกัส, safe-area iPhone
7. focus ด้วยคีย์บอร์ด/สวิตช์: วงแหวนเหลืองในแถบน้ำเงิน วงแหวนน้ำเงินบนพื้นขาว
8. screenshot ก่อน/หลังเพื่อยืนยัน skeleton ไม่ทำให้ layout กระโดด (CLS)

## 7. ความเสี่ยงและเรื่องที่ต้องตัดสินใจ

- **เหลืองบนขาวไม่มีขอบ**: เลือกยอมรับตามแบรนด์ (14.25:1 ของตัวอักษร) หากผู้ตรวจ a11y ต้องการเข้มงวด 1.4.11 ให้เพิ่มขอบ `2px solid var(--brand-dark)` ที่ปุ่ม primary ได้โดยไม่กระทบเทสต์
- **ความสูง skeleton**: เป็นจุดเสี่ยงสุดของ layout shift ต้องวัดจริง
- **ฟอนต์ Prompt**: ไม่บังคับ ถ้าไม่ฝัง ตัวหนา 800 จะขึ้นกับฟอนต์ระบบ (บาง Android ไม่มี 800 จะตกเป็น 700 ยังอ่านได้)
- **มาสคอต**: ภาพต้นฉบับละเอียดเพียง 186px จึงห้ามแสดงใหญ่กว่า ~72 CSS px
- **ข้อความ hero หน้าบิล** เป็นข้อความใหม่ (ยกจากภาพ Rich Menu) ขอให้เจ้าของโปรเจกต์ยืนยันถ้อยคำ
- สิ่งที่ผู้ใช้ยืนยันไว้แล้ว (เช่น ค่า UX ก่อนหน้าใน STATE.md) ไม่ได้ถูกเปลี่ยนในเอกสารนี้: ยังไม่ได้อ่านครบ ถ้า dev พบค่าที่ขัดกับ STATE.md ให้ถือว่าค่าที่ผู้ใช้ยืนยันมาก่อน
