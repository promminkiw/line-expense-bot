# P3 UX audit (2026-10-21, panda, read-only)

ขอบเขต: public/liff index.html, style.css, tokens.css, app.mjs และ *-panel.mjs; อ่านโค้ดอย่างเดียว ไม่ได้รันแอปหรือเปิดภาพ screenshot
ไม่รวมสิ่งที่ P1/P2/me-tab-menu แก้แล้ว และข้อที่ STATE.md ตัดสินแล้ว (ปัดแล้วกดปุ่มลบไม่มี modal, "เมนูแชต" ใน tip, ปุ่มจัดการหมวดหมู่ 2 ที่)
ภาพรวม: a11y ดีมาก (aria-label ครบ, focus ring, tap target 44px+, reduced-motion, token contrast มีเทสต์) รายการด้านล่างเป็นเรื่อง flow และความต่อเนื่อง ไม่มี BLOCKING

## รายการ P3 เรียงตามความสำคัญ

1. [WARNING] ปุ่มย้อนกลับของเครื่อง/ท่าปัดย้อนกลับ ออกจากเว็บทั้งหมดจากหน้าย่อย
   - ที่: app.mjs:1717-1746 (enterSubPage/leaveSubPage) ไม่มี history.pushState/popstate เลย (app.mjs ใช้แค่ replaceState ที่ :1889)
   - ทำไม: ผู้ใช้อยู่ในหน้า กระเป๋า/การแจ้งเตือน/เพื่อน แล้วกดย้อนกลับของ Android หรือปัดขอบ iOS คาดว่ากลับเมนู ฉัน แต่จะออกจาก LIFF ทั้งหมด เป็นข้อที่ STATE ข้อ 4 ฝากไว้ตัดสินตอน P3
   - แก้: pushState ตอน enterSubPage, ฟัง popstate แล้วเรียก leaveSubPage (ทำให้ปุ่ม #page-back เรียก history.back() ด้วย)
   - ขนาด: medium (ต้องดูเทสต์ DOM ที่ผูกกับ enter/leave และกรณีลิงก์ friend/bills)
   - ตรวจไม่ได้: พฤติกรรมจริงของ LINE webview บน Android/iOS ต้องทดลองบนเครื่อง

2. [WARNING] เปลี่ยนเดือนได้แค่ผ่าน native month picker ไม่มีปุ่ม ก่อนหน้า/ถัดไป
   - ที่: index.html:239 (`<input type="month">`), style.css:315 (#month กว้าง 132px)
   - ทำไม: ดูย้อนหลังทีละเดือนต้องเปิด picker ทุกครั้ง; picker ของ webview Android บางรุ่นใช้ยาก; เป็นการกระทำที่ทำบ่อยที่สุดในแท็บ รายการ/สรุป/งบ
   - แก้: เพิ่มปุ่ม ‹ › ข้าง #month (aria-label "เดือนก่อน/เดือนถัดไป", tap 44px) แล้วสั่ง change ที่ app.mjs:1274; ปิดปุ่มถัดไปเมื่อเป็นเดือนปัจจุบัน
   - ขนาด: medium (header แคบ ต้องจัด layout ที่จอ 320-360px)

3. [WARNING] ค่าเริ่มต้นการเลื่อนหน้าถูกรีเซ็ตทุกครั้งที่สลับแท็บ/กลับจากหน้าย่อย
   - ที่: app.mjs:1664 (onChange -> window.scrollTo(0,0)), และ leaveSubPage app.mjs:1743 เรียก select(force) ทำให้ scrollTo(0,0) ซ้ำ
   - ทำไม: เลื่อนรายการยาวๆ ไปแท็บสรุปแล้วกลับ ต้องเลื่อนหาตำแหน่งเดิมใหม่; เปิดเมนู ฉัน -> หน้าย่อย -> กลับ แล้วกลับมาบนสุดแทนแถวที่กดไว้ (focus ไปที่แถวแต่หน้าไม่เลื่อนตาม)
   - แก้: เก็บ scrollY ต่อแท็บใน tabController แล้วคืนค่าตอนสลับกลับ; ตอน leaveSubPage คืนตำแหน่งเดิมของแท็บเจ้าของหน้า
   - ขนาด: small-medium
   - ตรวจไม่ได้: ความรู้สึกจริงบนมือถือ (jsdom ไม่มี scroll จริง)

4. [WARNING] ข้อความ error ในกล่องแก้ไข (dialog) อยู่ล่างสุด อาจอยู่นอกจอเมื่อคีย์บอร์ดเปิด
   - ที่: index.html:667-668 (edit-busy/edit-error), :826-827 (budget), กับ recurring/goal editor; dialog สูงสุด 92dvh เลื่อนเองได้ (style.css:24)
   - ทำไม: กดบันทึกแล้วล้มเหลว (เช่น 409/ออฟไลน์) บนจอเล็กขณะคีย์บอร์ดค้าง ผู้ใช้เห็นปุ่มเงียบๆ ไม่รู้ว่าพลาด (screen reader ได้ยินจาก role=alert แต่คนทั่วไปไม่เห็น) ต่างจาก friends-panel.mjs:135 และ bills-panel.mjs:54 ที่ scrollIntoView แล้ว
   - แก้: helper กลางเรียก error.scrollIntoView({block:'nearest'}) ตอนแสดง error ของ editor ทุกตัว
   - ขนาด: small
   - ตรวจไม่ได้: ต้องให้ hawk ทดสอบจอ 320px พร้อมคีย์บอร์ดจริง

5. [WARNING] เมนู ฉัน: แถวที่ disabled ไม่บอกเหตุผล และไม่มีทางหายถ้า LIFF init ล้ม
   - ที่: index.html:483,492,506,515,529 (disabled ตั้งต้น), app.mjs:1893 (เปิดหลัง login), style.css:469 (สีเทาอ่อน opacity 0.5 ที่ไอคอน)
   - ทำไม: ระหว่างรอ หรือเมื่อ /api/config ล้ม ผู้ใช้เห็นแถวเทากดไม่ได้โดยไม่รู้ว่าทำไม (banner ขึ้นที่อื่น); แถวหมวดหมู่ (app.mjs:520) disabled ตามจำนวนหมวดด้วยเหตุผลต่างกัน แต่หน้าตาเดียวกัน
   - แก้: ใส่ sub text สั้นๆ ตอน disabled เช่น "กำลังเตรียม..." หรือไม่ disabled แต่ให้หน้าย่อยแสดง loading/error ของมันเอง (ส่วนใหญ่มี ensureLoaded อยู่แล้ว)
   - ขนาด: small

6. [WARNING] skeleton ของแท็บ ฉัน ยังมีการ์ด "tips" ที่ย้ายออกไปแล้ว
   - ที่: app.mjs:209 (variants รวม 'tips'), style.css:199 (.skeleton-tips สูง 203px)
   - ทำไม: ตอนโหลดโปรไฟล์ เห็นกล่องเทาสูง 203px แล้วหายพร้อมเมนูเลื่อนขึ้นมาแทน หน้าขยับ (layout shift) และสื่อผิดว่าจะมีการ์ดวิธีใช้
   - แก้: เปลี่ยน variant 'tips' เป็นรูปแถวเมนู (ความสูงตาม .menu-group) หรือเอาออก
   - ขนาด: small
   - ตรวจไม่ได้: ต้องดูจริงว่าเมนูโชว์ระหว่างโหลดหรือไม่ (index.html:479 menu-groups ไม่ผูกกับ profile-card hidden)

7. [INFO/WARNING] ปัดแถวเพื่อลบไม่มีคำใบ้ให้ค้นพบ
   - ที่: app.mjs:591-625 (swipe), index.html:250-278 (ไม่มีข้อความบอก), empty-state.mjs:6 (hint ของ list พูดแต่การพิมพ์ในแชต)
   - ทำไม: ท่าเดียวที่ลบแบบเร็วซ่อนอยู่ (ลบผ่านตัวแก้ไขได้อยู่แล้ว จึงไม่ blocking) ผู้ใช้ใหม่ไม่รู้ ผู้ใช้ keyboard/screen reader ใช้ไม่ได้ (ต้องเปิดตัวแก้ไข)
   - แก้: ข้อความเล็กๆ ใต้ filter ครั้งแรกที่มี >=1 แถว "ปัดแถวไปทางซ้ายเพื่อลบ" ปิดได้แล้วจำใน localStorage หรือเพิ่มเป็นข้อใน หน้าวิธีใช้งาน (index.html:633-640) ซึ่งเป็นทางที่เบาที่สุด
   - ขนาด: small
   - หมายเหตุ: ไม่ขัดกับที่ตัดสินแล้ว (ตัดสินเรื่องไม่มี modal ไม่ใช่เรื่อง hint)

8. [INFO] ข้อความ truncated ชี้ไปที่ Export CSV ในแท็บอื่น แต่ไม่มีทางลัด

9. [INFO] ช่องจำนวนเงินใช้ type=number ไม่รับคอมมา ต่างจากฟอร์มบิลที่เป็น text+inputmode

12. [INFO] ขนาดตัวอักษรเป็น px ทั้งหมด และข้อความรองจำนวนมากเป็น 13px สี muted
    - ที่: style.css (เช่น :15-17, :97, :216, :304, :475) และ tokens.css:--muted #556070
    - ทำไม: contrast ผ่าน (มีเทสต์) แต่ 13px + เส้นไทยบาง อ่านยากสำหรับผู้สูงอายุ/เปิดแสงจ้า และไม่ตามการตั้งขนาดตัวอักษรของ LINE ใน iOS
    - แก้: ยกขั้นต่ำเป็น 14px ของข้อความรอง หรือเปลี่ยนเป็น rem; ทำแยกเป็นงานเล็กๆ ที่ไม่เสี่ยง layout
    - ขนาด: medium (กระทบความกว้างของ stat/summary ที่ปรับ clamp ไว้แล้ว ต้องดู screenshot ทุกแท็บ)
    - ตรวจไม่ได้: ต้องดูภาพจริงที่ 320px

## สิ่งที่ตรวจแล้วไม่พบปัญหา (ไม่ต้องทำ)
- aria-label ของปุ่มในแถว (ลบรายการ/แก้หมวด/เปลี่ยนชื่อกระเป๋า/ลบเพื่อน), aria-pressed/expanded, role=status/alert ของ loading/error, ปุ่ม ลองใหม่ ในทุกส่วนที่โหลดข้อมูล, focus กลับไปที่แถวต้นทางหลังปิดหน้าย่อย/ลบแถว, prefers-reduced-motion
- ปุ่มปิด dialog 44px, ปุ่มอื่น >= 44px, ปุ่ม disabled มีเส้นประ+สี (ไม่ใช้สีอย่างเดียว)

## ข้อจำกัด
อ่านโค้ดอย่างเดียว ไม่ได้เปิดแอป/ภาพ screenshot และไม่ได้รันเทสต์ ทุกข้อที่เกี่ยวกับการเลื่อนหน้า คีย์บอร์ดมือถือ ปุ่มย้อนกลับของ LINE และการดาวน์โหลด CSV ต้องให้ hawk หรือผู้ใช้ตรวจบนเครื่องจริงก่อนลงมือแก้
